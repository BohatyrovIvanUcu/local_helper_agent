# Чекліст тестування оновленого асистента (`TESTING_CHECKLIST.md`)

Цей документ містить покрокові сценарії для ручної та автоматичної перевірки всіх оновлених модулів: безпеки команд, кнопок підтвердження в UI, парсера дат, інтеграції з Obsidian, таймерів, медіа та саммарі браузера.

---

## Частина 1. Автоматичні тести та збірка (1 хвилина)

Перед тестуванням у графічному інтерфейсі переконайся, що всі unit-тести та типи проходять успішно:

```bash
# 1. Запуск тестів TypeScript (дати, політика безпеки, оркестратор, системний промпт, реєстр)
npm test

# 2. Запуск тестів Rust (парсинг Obsidian, токенізація CLI, захист шляхів, дедуплікація)
PATH="$HOME/.cargo/bin:$PATH" cargo test --manifest-path src-tauri/Cargo.toml

# 3. Перевірка компіляції та production-бандла Vite
npm run build
```

**Очікуваний результат:**
- `npm test`: 34 passed (0 failed).
- `cargo test`: 7 passed (0 failed).
- `npm run build`: успішна збірка без помилок TypeScript.

## Частина 3. Сценарії перевірки функціональності

### Сценарій 1. Безпечні команди CLI (Автоматичний Allowlist без підтвердження)
> **Мета:** Перевірити, що безпечні команди читання та відкриття браузера виконуються відразу без зайвих кліків.

- [ ] **Тест 1.1 (Git статус):**
  - **Запит:** `Який поточний статус git у проекті?`
  - **Очікувана поведінка:** Маскот одразу переходить у `THINKING` -> `WORKING (Термінал)` -> видає результат `git status`. Жодних кнопок підтвердження не з'являється.
- [ ] **Тест 1.2 (Читання файлів/директорій):**
  - **Запит:** `Покажи вміст поточної папки` (або `Виведи ls -la`)
  - **Очікувана поведінка:** Виконується команда `ls`, маскот лаконічно перелічує основні файли.
- [ ] **Тест 1.3 (Відкриття браузера):**
  - **Запит:** `Відкрий google.com у браузері`
  - **Очікувана поведінка:** Браузер відкриває сторінку через `xdg-open` без запиту підтвердження.

### Сценарій 2. Ризикові команди та інтерактивні кнопки підтвердження в UI
> **Мета:** Перевірити роботу нових кнопок `[Підтвердити]` та `[Скасувати]` у бульбашці маскота.

- [ ] **Тест 2.1 (Скасування запуску скрипту):**
  - **Запит:** `Виконай команду: python3 -c "print(12345)"`
  - **Очікувана поведінка:**
    1. У бульбашці маскота з'являється жовта іконка ⚠️, заголовок `"Потрібне підтвердження команди"`, моноширинний блок із командою та дві кнопки: `[Скасувати]` та `[Підтвердити]`.
    2. **Перевірка таймера:** Зачекай 20 секунд (довше стандартного 16-секундного ліміту). Маскот **не повинен** зникати чи повертатися в IDLE — бульбашка чекає твого вибору!
    3. Натисни кнопку **`[Скасувати]`**.
    4. **Результат:** Модель отримує статус скасування і відповідає: «Зрозумів, команду скасовано». Команда в терміналі не виконувалася.
- [ ] **Тест 2.2 (Підтвердження запуску скрипту):**
  - **Запит:** `Запусти команду: python3 -c "print('Тест пройшов успішно!')"`
  - **Очікувана поведінка:**
    1. Знову з'являється бульбашка з кнопками.
    2. Натисни **`[Підтвердити]`**.
    3. **Результат:** Маскот переходить у `WORKING (Термінал)`, виконує скрипт і відповідає із виведеним текстом `"Тест пройшов успішно!"` у своєму характері будівельника.
- [ ] **Тест 2.3 (Деструктивна команда — видалення):**
  - **Запит:** `Спробуй видалити /tmp/non_existent_test_file.txt через rm`
  - **Очікувана поведінка:** З'являється запит підтвердження з командою `rm ...`.

### Сценарій 4. Робота з Obsidian TODO.md та детермінованими датами
> **Мета:** Перевірити виправлений парсер секцій (## TO DO замість ## Ideas), відносні дні тижня та відсутність видалення чужих рядків.

- [ ] **Тест 4.1 (Задача на завтра):**
  - **Запит:** `Запиши в туду: здати архітектурний звіт на завтра`
  - **Очікувана поведінка:**
    1. Відкрий свій файл `TODO.md` в Obsidian.
    2. Переконайся, що задачу додано під заголовок `## TO DO` (а **не** `## Ideas`).
    3. Переконайся, що дата в кінці рядка має правильний формат: `@{РРРР-ММ-ДД}` (завтрашня дата в локальному часі).
- [ ] **Тест 4.2 (День тижня українською):**
  - **Запит:** `Додай задачу: в п'ятницю зробити резервну копію бази даних`
  - **Очікувана поведінка:** У `TODO.md` з'являється чекбокс із дедлайном найближчої п'ятниці.
- [ ] **Тест 4.3 (Збереження інших секцій):**
  - **Запит:** Додай задачу, текст якої вже є в іншій секції (наприклад, у `## DONE`).
  - **Очікувана поведінка:** Запис у `## DONE` залишається на місці і не стирається (виправлено баг старого парсера).

## Частина 4. Підсумок успішного тестування

Якщо всі пункти виконані успішно:
1. Маскот працює без зависань при довгих роздумах або очікуванні кліків.
2. Жодна небезпечна або невідома команда не виконується без явного дозволу користувача.
3. Дошка `TODO.md` та таймери ведуться стабільно і передбачувано.
4. Характер маскота-будівельника зберігається у всіх відповідях після викликів інструментів.
