# Local Helper Mascot — Базові правила та Архітектура Проєкту

Цей документ визначає фундаментальні архітектурні принципи, структуру кодової бази, правила розробки та суворий регламент створення релізів для проєкту **Local Helper Mascot**.

---

## 1. Що це за проєкт

**Local Helper Mascot** — це швидкий локальний десктопний AI-асистент з інтерактивним маскотом, побудований на:
- **Tauri v2** (Rust + WebKit/GTK на Linux, WebView2 на Windows, WKWebView на macOS).
- **React 19 + TypeScript + Tailwind CSS** на фронтенді.
- **Google Gemini API** (моделі `gemini-3.5-flash-lite`, `gemini-2.5-flash`, `gemini-2.5-pro`) з Function Calling.
- **Нативних системних інтеграціях** без відкриття сторонніх вікон налаштувань:
  - PipeWire / PulseAudio / ALSA (гучність, мікрофон).
  - GNOME Mutter D-Bus / `gsettings` / `brightnessctl` (яскравість екрана, нічний режим).
  - MPRIS v2 / YouTube Music / Spotify (керування музикою та медіа).
  - Obsidian Kanban & Markdown (нотатки, задачі, дедлайни).
  - VS Code workspace detection (визначення активного проєкту та файлу).

---

## 2. Модульна архітектура бекенду (Rust / `src-tauri`)

> [!IMPORTANT]
> **ЖОДНОГО МОНОЛІТНОГО КОДУ В `lib.rs`!**
> Файл `src-tauri/src/lib.rs` є лише точкою збирання та реєстрації модулів, обробників подій вікна та системного трею (~100-150 рядків коду). Будь-яка нова функціональність або розширення існуючої пишеться **виключно в окремому файлі** у `src-tauri/src/`.

### Структура модулів у `src-tauri/src/`:
- **`audio.rs`**: Системне керування аудіо та гучністю (PipeWire `wpctl`, PulseAudio `pactl`, `amixer`, macOS `osascript`).
- **`display.rs`**: Системна яскравість та колірна температура (GNOME Mutter D-Bus `SetBacklight`, `gsettings` night light, `brightnessctl`, `xrandr`, Windows WMI).
- **`config.rs`**: Читання/запис конфігурації (`~/.config/local-helper-ai/config.env`), `expand_tilde`, санітизація шляхів Vault.
- **`files.rs`**: Безпечні операції з файлами (`create_or_update_file`, `read_file_or_dir`, `run_cli_command`, перевірка `is_sensitive_path`).
- **`workspace.rs`**: Визначення активного проєкту та відкритого файлу у VS Code (`get_active_workspace`).
- **`obsidian.rs`**: Інтеграція з нотатками Obsidian, Kanban-дошками, секціями та дедлайнами (`append_to_obsidian`).
- **`media.rs`**: Керування відтворенням медіа, пошук у YouTube Music, MPRIS D-Bus (`control_media`, `is_music_playing`).
- **`memory.rs`**: Довгострокова пам'ять фактів та історія діалогів (`get_agent_memory`, `append_conversation_turn`, `manage_memory`).
- **`reminders.rs`**: Планування нагадувань і таймерів, фоновий потік моніторингу часу та системних сповіщень (`manage_reminders`).
- **`voice.rs`**: Запис голосу з мікрофона (PipeWire `pw-record` / ALSA `arecord`), генерація Base64 WAV.
- **`clipboard.rs`**: Зчитування зображень та скриншотів із системного буфера обміну (GTK).
- **`web.rs`**: Читання та парсинг активної вкладки браузера / зовнішніх посилань для саммарі (`summarize_webpage`).
- **`window.rs`**: Керування вікном маскота (Always-on-top, інтерактивність у Wayland/X11, розміри `280x258` vs `380x440`).
- **`main.rs`**: Консольний CLI-інтерфейс (`addkey`, `set-model`, `set-vault`, `config`, `--help`).

## 3. Гібридний підхід: Fast-Path vs LLM Function Calling

Система поєднує надшвидку апаратну реакцію із гнучкістю штучного інтелекту:

1. **Рефлекторний Fast-Path (`src/agent/orchestrator.ts`)**:
   - Команди керування мультимедіа (наприклад: *«пауза»*, *«гучніше»*, *«зроби тихіше»*, *«звук на 0»*, *«музика»*).
   - Команди керування екраном (наприклад: *«зменш яскравість до 30%»*, *«увімкни нічне світло»*, *«вимкни теплий екран»*).
   - **Швидкість**: виконуються за <30 мс напряму через системні виклики Rust, без звернення до Gemini API (нуль затримки, нуль витрат токенів).
2. **LLM Function Calling (`src/agent/`)**:
   - Складні розмовні запити, багатоходові завдання, контекстні інструкції, робота з нотатками, кодом, консольними командами.
   - Обробляються через Gemini API з використанням `ToolRegistry` та суворої типізації аргументів.

## 4. Політика безпеки (`SafetyPolicy`)

Безпека користувача є абсолютним пріоритетом:
- **Заборона ескалації привілеїв**: команди `sudo`, `su`, `doas` заборонені в системі.
- **Захист конфіденційних файлів**: заборонено читання та запис у `.ssh`, `.gnupg`, `.aws`, `/etc/shadow`, `.env`, `config.env`.
- **Захист від небезпечних дій**: деструктивні CLI-команди (`rm -rf`, `mkfs`, редагування коду) вимагають обов'язкового підтвердження користувача через UI діалог.
- **Ізоляція зовнішнього контенту**: веб-сторінки поміщаються в тег `<untrusted_web_content>` із захистом від prompt injection та taint-маркуванням поточної сесії.

## 5. Стандарти коду та обов'язкова валідація

1. **Мінімальні зміни**: Не додавати зайвих абстракцій, обгорток чи бібліотек без реальної потреби.
2. **Збереження сумісності**: Не ламати існуючі API між TypeScript та Rust (`tauri::generate_handler!`).
3. **Обов'язковий прогін тестів після кожної зміни**:
   ```bash
   # 1. Перевірка та юніт-тести бекенду на Rust:
   cargo test --manifest-path src-tauri/Cargo.toml

   # 2. Юніт-тести фронтенду та агента:
   npm test

   # 3. Перевірка типів TypeScript:
   npx tsc --noEmit
   ```
4. **Збірка релізного пакунка**:
   ```bash
   npm run build:deb
   ```

## 6. Алгоритм підготовки та створення релізу (CI/CD GitHub Actions)

> [!IMPORTANT]
> **ЯК ПРАЦЮЄ РЕЛІЗ У ПРОЄКТІ:**
> У проєкті підключено автоматичний мультиплатформний GitHub Actions CI/CD (`.github/workflows/build-deb.yml`).
> Він автоматично збирає пакунки для **Linux (`.deb`)**, **Windows (`.exe`)** та **macOS (`.dmg`)**, створює GitHub Release і бере опис **виключно з файлу `releases/RELEASE_TEMPLATE.md`** через прапорець `--notes-file`.

### Порядок дій для асистента при кожному релізі:

1. **Підняти версію у 3-х файлах**:
   - `package.json` (`"version": "X.Y.Z"`)
   - `src-tauri/Cargo.toml` (`version = "X.Y.Z"`)
   - `src-tauri/tauri.conf.json` (`"version": "X.Y.Z"`)

2. **ОБОВ'ЯЗКОВО оновити `releases/RELEASE_TEMPLATE.md`**:
   - Записати актуальний номер версії `vX.Y.Z`.
   - Детально описати нові функції, виправлення помилок та зміни.
   - Оновити шляхи до завантаження та команди встановлення.
   *(Якщо цього не зробити, GitHub Actions опублікує реліз зі старим описом попередньої версії!)*

3. **Перевірити тести та зібрати локальний `.deb`**:
   ```bash
   cargo test --manifest-path src-tauri/Cargo.toml
   npm test
   npx tsc --noEmit
   npm run build:deb
   ```

4. **Надати користувачеві ОДНУ готову команду для терміналу**:
   Асистент НЕ пушить сам, а надає користувачеві готову команду в один рядок, яка комітить зміни, оновлює тег і пушить на GitHub:
   ```bash
   git add . && git commit -m "feat: release vX.Y.Z — <опис>" && git tag -a vX.Y.Z -m "Release vX.Y.Z" && git push origin main && git push origin vX.Y.Z
   ```
   *(або через `--amend` та `--force`, якщо коміт уже створено)*.
   Далі GitHub Actions повністю автоматично створює реліз з описом та файлами.

## 7. Правила взаємодії та Git

- **НЕ ПУШИТИ В РЕПОЗИТОРІЙ САМОСТІЙНО**: користувач самостійно контролює відправку коду в GitHub (`git push`). Асистент тільки готує зміни, перевіряє тести та звітує.
- **Мова спілкування**: українська мова для всіх відповідей та коментарів до функціоналу.
- **Стислість та точність**: короткі звіти зі списком змінених файлів та результатами перевірок.
